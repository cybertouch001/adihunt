WHAT IS NEW
* Live Match: lobby by 6-letter room code, 3 to 12 players, one Seeker (random at start), hiders.
* Shrinking safe zone: the host's radius (150/300/500/800 m live; 60/100/150 m virtual), random centre inside the radius, every next circle
  nested inside the previous one; a stage every 2 min (live) or 90 s (virtual). A hider outside the zone with a fresh position for 45 s is out.
* Seeker ping every 2 minutes (first ping at release): everyone's last position, or "no signal" for a hider with no fresh fix.
* Tag: live reach 15 m, virtual 4 m; only the Seeker, only a live hider with a fix from the last 30 s. A hider's own position is never sent to the Seeker outside a ping, a radar or (virtual) the field of view.
* Radar: 2 per Seeker, returns distance (5 m steps) and bearing (15 deg steps) of hiders within 400 m. No names, no coordinates.
* Decoys: 2 per hider; the next ping shows a spot ~90-150 m away instead of the real one.
* Head start (0/1/2/5 min), match time limit (10/15/20/30 min), visibility setting (nobody / hiders see each other / friends see each other).
* Host: End match button; Leave; Close room in the lobby.
* Scoreboard, ranks Bronze/Silver/Gold/Platinum/Diamond from match points, route replay for players (kept 24 h after the match).
* Anti-cheat: move speed check per post (live 10 m/s + 30 m slack, virtual 8 m/s + 2 m slack), accuracy above 80 m ignored, positions only while a match is running, last positions cleared at the end, the Seeker's field of view computed on the server.
* Virtual arena: OpenStreetMap building footprints (Overpass, free, no key) for the host's real place, rendered with three.js (vendored, MIT). If Overpass is unreachable the arena falls back to a generated block layout (labelled in the HUD data attribute only).
* Landscape: the web game asks the Android shell for landscape only during a virtual match (AdiHuntNative.orient); the rest of the app stays portrait. On the web, a rotate prompt shows in portrait.
* Schema: 7 new tables (matches, match_players, match_pings, match_events, match_trail, match_stats) created with CREATE TABLE IF NOT EXISTS. No existing table is altered.
* Match XP: +20 per match played, +80 for a win (applied through the existing reward path). Existing XP totals are not changed by the deploy.

NAMING

* No personal name, phone number or address appears in the app, the site or the repo.

NOT TESTED
* The Android APK was never run: no emulator, no /dev/kvm. The build is signed and the manifest and bridge are inside the APK, but a phone has not run it.
* Real phones, real GPS accuracy across several people, GPS lag between players, battery use, background behaviour.
* The WebView landscape switch on a real device (AdiHuntNative.orient) is untested. The manifest still says portrait; the runtime request overrides it.
* Migration on a copy of live data: NOT done as a copy. The change is additive (new tables); the live D1 binding was reused (not recreated) and the before/after XP check passed.
* Load: no load test. Positions are short-polled (1 request per second per player in the arena, one per 2-3 s live). A large room (12 players for a long match) has not been measured against D1 limits.
* Overpass (OSM buildings) answered HTTP 406 to this box's request during the build, so the browser test's arena used the generated block fallback. Real OSM buildings were NOT exercised in a browser here; the loader's code path is untested against live data.
* No touch joystick: the on-screen controls are a D-pad (hold to move, turn left and right).

KNOWN LIMITS
* Live mode: a hider whose phone stops sending positions is not eliminated by the zone (no fresh fix means no zone check), and shows as "no signal" in the ping.
* The first ping at release can predate the first GPS fixes; hiders then show as no signal in that ping.
* Friends visibility uses the existing friends list (rows are written in both directions by the social API).
* Match timers run on the server clock; the phone clock only draws the countdown.
* Polling, not sockets: a match state is refreshed by short-polls (about once a second in the arena, every 2 s live) - simple and robust on Cloudflare D1, but chattier than a socket.
